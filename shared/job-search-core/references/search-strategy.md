# 搜索策略与范围

薪资不作为搜索/清洗/排除条件，城市只按用户明确的城市范围处理；同城距离/通勤需求告知不支持并忽略，不派生后续采集或核验目标。软城市偏好记录city_preference，不擅自转为city_filters硬排除。

先读 decision-policy.md。这里区分三个独立维度：公司/行业/城市/方向的搜索范围；exhaustive/targeted 的获取策略；sample/companies/all 的评估范围。执行批次不等于总评估范围。

用户表达某种岗位倾向（如“想找项目管理相关岗位”）且尚未明确搜索方式时，必须先向用户说明以下取舍并请其选择，再启动依赖该选择的岗位采集。仅表达倾向、提供关键词或要求“快点”，都不等于确认标题定向搜索。已有明确选择直接沿用，不重复确认；等待选择时可继续整理行业、公司和现有材料。

| 用户选择 | 执行方式 | 优点 | 局限 |
| --- | --- | --- | --- |
| 岗位标题相关定向搜索 `targeted` | 按确认的标题词及合理近义词搜索，取得命中岗位的完整 JD | 通常更快，减少无关结果；API 支持时减少列表传输和详情请求 | 可能漏掉标题不含相关词、但实际职责相关的岗位；API 未证实支持时仍须获取全量列表，速度收益不保证 |
| 全量 JD 获取后综合判断 `exhaustive` | 获取约定范围内岗位的标题和完整 JD，结合职责、要求判断与岗位倾向的相关性 | 能发现标题不典型但工作内容相关的岗位，覆盖更充分 | 请求、耗时和全文分析量更大；仍受来源可访问性及采集完整性限制 |

询问示例：“你想按岗位标题相关词定向搜索，还是获取本次范围内的全量 JD，再结合标题和正文判断相关性？前者通常更快，但可能漏掉标题不同的相关岗位；后者覆盖更充分，但耗时更长。”用户明确要求全量时直接使用 exhaustive；没有岗位倾向且未选择定向时也沿用 exhaustive。全量均指本次约定的公司、招聘方向、地区和来源范围，不是全网。

只有用户确认 targeted 且对应数据 API 已证实支持，才使用服务端关键词搜索；两个条件同时满足时必须使用，不得先抓全量再本地筛选。按每个来源配置和招聘方向分别判定，不能用同平台或其他公司的证明代替。未证实支持、不支持、证明缺失或配置变化导致证明失效的来源，完整分页获取同范围岗位列表后在本地筛标题，再取得命中 JD；这是定向模式的兜底，不改变用户选择。选择 exhaustive 时，即使 API 支持关键词也不做关键词预筛，必须通过标题和 JD 正文综合判断相关性。

targeted 的计划、语义扩词、公司依据和能力核验按 [定向检索](targeted-search.md)。执行前简要展示候选公司与词表，已授权不重复确认；native 查询不能信任参数名，仍按已验证能力回退。关键词命中只代表候选，不是能力或个人意愿评分。零命中先解释限制，未经用户要求不扩范围。

已有城市硬筛政策保留：对应方向的公司城市标签未命中则不采集，未知/部分标签也可能排除；如实说明“当前标签未命中”和日期，不能说公司确定无招聘。无城市条件不收窄。城市索引只在独立主动维护流程刷新；首次使用、过期或缺失也不自动初始化，不要求求职用户先维护。collect / collect --refresh 仅获取本轮岗位，不回写城市索引。来源配置变化不能沿用旧能力证明。

采集后展示公司、可评估、待核实、失败/部分覆盖数量；用户已经给出 sample 数量、指定公司或 all 时直接 plan-assessment。未明确时才问。不能因岗位多自行抽样。

“前N个”必须以展示顺序固定岗位键；“抽样N个”可用现有轮流公司抽样；“最适合N个”需要说明比较母集、完成该范围评估再选，不能抽样冒称最佳。批次只是把已承诺工作分段，不降低全文要求。“继续下一批”先读取剩余，不重采相同快照；用户说最新则刷新。

任务变化：新范围 prepare 新运行，可 reuse-run 复用同方向/配置/策略的JD，不复用变更画像后的评级。定向计划有独立指纹；不能把定向快照当全量或写入全量城市缓存。输出目录由方向运行隔离。

## 通用职能相关性审阅

求职与雷达使用同一 `role-relevance.mjs` 契约：岗位键、JD 指纹、目标/排除条件指纹、规则版本，结论 related/unrelated/uncertain、解释及 JD 原文引文。正文不足只能 uncertain。Agent 阅读全文作判断；CLI 不用标题词替代全文语义。

求职全量有岗位目标时，collect 后执行 `role-review-export --mode 方向 --run 目录`，将返回 items 加入判断字段，再 `role-review-submit --mode 方向 --run 目录 --file 判断.json`。两者前缀均为 `node job-search/scripts/jobs.mjs`。未完成前可 render-discovery 交付待审中间清单；进入个人评估必须先完成职能审阅。不相关岗位排除，uncertain 留待确认，个人匹配仍独立按 v5 执行。

雷达使用 review-export/review-submit/finalize，见[运行约定](../../../job-radar/references/operations.md)。相同目标与未变 JD 复用判断，改正文或目标后重审；每轮仍重新采集列表。缺失正式城市索引且存在城市硬条件时报告数据不可用，不当成零公司或自动初始化。
