# 公司标签分类与证据标准

此文用于主动维护。日常求职直接使用保存结论，不重新调查、不触发刷新、不向求职用户补问标签维护问题。

公司字段由私有维护链路复核并发布，公开使用方式见[工程与数据发布边界](repository-management.md)。本文的分类口径和供应商优先级继续有效。

## 标签维度

| 维度 | 口径 | 依据与边界 |
| --- | --- | --- |
| 行业 | 招聘主体经营活动的宽类，可多值，搜索多选取并集 | 使用 industry-routing.mjs 中已发布的36类及其ID，定义见[行业分类](industry-taxonomy.md)；根据主体业务资料归类，不根据单个招聘岗位职能归类 |
| 业务 | 主体提供的具体产品/服务，可多值 | 保存 business_tags 与简短 business_summary；明确客户/产品/服务及主体范围；“项目管理”“HR”等职能不作雇主主营业务 |
| 性质 | 招聘主体的所有制/控制关系 | 现有国企、私企、外企、待核实四个展示值；状态另存 demo_unreviewed/api_supported/verified/verified_unresolved/unknown，不从公司名称、上市地点或办公地点推断 |
| 招聘城市 | 某招聘主体、某招聘方向下观察到的开放岗位地点 | 来源是目标类型的官方岗位；总部、注册地址、宣讲会地点、第三方公司城市提示不替代岗位地点 |

行业和业务不能互相替代：例如“软件、云与 IT 服务”可包含网络安全、云服务等不同业务；招聘项目管理岗不使公司归入咨询行业。集团有某业务不证明所有子公司或所有岗位都涉及该业务；按已核验 company_id 保存主体口径，沿用主体核验规则。

## 现有行业体系的处理

分类ID、名称、别名和描述的唯一可执行来源为 `scripts/lib/industry-routing.mjs`，公司已发布归属读取 `data/company-records.json`。业务词表、别名和包含/排除定义在 `data/business-taxonomy.json`。其中 legacy 词条保留历史含义，不表示已经完成全部同义词合并。

## 基于正式描述的标签修正

主动维护可先读取公司简介和产品服务，由 Agent 判断主体实际提供的业务。程序负责候选扫描、词表校验、来源摘录校验、差异与发布，不以命中关键词代替判断。客户行业、应用场景、招聘职能、集团其他主体的业务均不能直接赋值。

例如“游戏研发与全球发行”支持业务“游戏研发、游戏发行”，行业为 games；没有明确运营描述时不额外增加“游戏运营”。游戏工具和美术外包分别保存，不自动命中“游戏”产品经营范围。

本地判断沿用 Demo 授权：正式可检索，状态为 demo_unreviewed，origin 为 local_description_classification；依赖原简介和产品服务，不能因此升级成独立核实。保留基线、逐公司处置、字段前后值、原句、词表版本及发布事务备份。普通字段修正保留独立核实保护。行业体系迁移必须完整重审并归档旧值与核实依据，新结论不继承旧口径核实状态；资料不足的行业置空且明确待判定，不沿用退役行业。其他缺失/冲突字段保留原值并留待维护；先读归档原件，只有事实缺失或主体冲突才按统一联网维护入口补证。

分类变更在私有维护链路按数据与词表版本审核，再投影正式画像及兼容文件。公开产品只读取已发布结果，不提供分类修改或发布命令。

旧目录混合宽行业、产品和供应链位置。现行体系按实际经营的产品和服务划分，多选仅用于有明确独立业务事实的主要板块。不能靠批量关键词替换解决。更换目录前须形成每类定义、包含/排除范围、正反例、新旧ID关系及用户条件迁移方式、受影响主体与搜索范围差异，先审核再迁移；迁移前继续沿用已发布枚举，不静默撤销旧ID。新分类标准不得反过来当作旧公司已经重新核实的证据。

## 判断依据与信息来源

- 行业/业务：读取主体官方业务/产品介绍、公开报告中的明确事实；JD 可证明具体团队或岗位涉及某业务，不独立证明该业务是整个集团主营。第三方介绍保留来源与主体关联依据，不用搜索摘要冒充已读正文。
- 性质：沿用已批准的供应商结构化性质字段第一优先级；没有该明确结论时，可靠关联的 Waiqi 详情明确标注“外企”可补充。合资不自动映射外企；供应商冲突多选、事业单位等不能强归三类。其他公开资料处理剩余主体；改变优先级需另审。
- 招聘城市：官方岗位地点及现有地点标准化证据。校招、实习、社招分别索引；多个招聘入口覆盖与冲突继续按现有采集规则记录。按关键词获得的局部岗位不得替换完整城市集合。

每次维护保存 company_id、标签值、状态、具体判断理由、资料主体口径、核实日期及来源（URL、标题、事实摘录/说明、证据类型、来源时间如有）。使用现有字段：性质 reason/checked_at/evidence；业务 business_summary/status/evidence，证据含 checked_at；城市 city_evidence/result_file/source_config_fingerprint/coverage。`demo_unreviewed` 表示首版正式可用但尚未独立复核，`api_supported` 表示 API 有来源支持，`verified` 才表示独立核实。联网材料没有给出可用事实时保留“待核实”或明确缺口说明，不把占位值当作事实证据。

## 维护生命周期

稳定标签核实后固定复用，仅主动维护修改。普通搜索发现的岗位只进入本次运行，不自动推导或回写公司行业/业务/性质/城市。城市可更频繁主动维护，但本轮不设置定时器或过期自动刷新。

城市完整覆盖且地点、类型、状态明确时可更新当前集合（包含完整空结果）；部分采集保留历史城市并补充新观察，失败保留旧值及失败状态。刷新前保存旧索引。现有标签仍只说明观察范围，不能把未记录解释为公司在该城市确定没有招聘。

维护结果需给出范围、改前/改后、证据、失败/未决项及实际写入文件。使用层 prepare 固定快照；维护不改既有运行的标签快照或评级。公司资料无效/缺失时使用层显示暂无资料，并在运行证据中保留原记录；严格资料校验由维护入口执行。
