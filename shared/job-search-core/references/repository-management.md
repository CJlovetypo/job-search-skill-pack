# 工程与数据发布边界

公有产品目录是 job-search、job-radar 和 shared。正式公司画像、招聘来源及 API 配置、招聘城市、方向和关键词能力均随版本公开，日常运行不依赖私有仓库、datasets、docs 或维护者路径。

## 读取与维护职责

公有产品只读正式数据，可写个人岗位缓存、简历匹配结果和运行报告。正常匿名初始化、HTTP 跳转、有限重试及已发布来源的并行采集属于采集；不得发现替代来源、变更招聘源配置、回写城市或接口能力，也不加载本机修复覆盖。失败与真实零岗位分别呈现。

维护由独立私有仓库承担：多渠道发现、主体判断、新公司创建、已有来源修复与扩源、字段审核、城市刷新、接口能力核验、发布和恢复。公有产品不分发维修 Skill、命令、策略开关或维护执行代码。用户反馈只作为待核查线索，默认不上传个人资料和运行记录。

私有主数据是唯一维护来源；公有文件是已批准版本的分发投影。正式画像是主体全集，招聘源库是可采集主体子集。保留既有 company_id/source_id、无源主体和集团／子机构边界；等价 API 可以登记别名，独立 API 可以互补。未决字段不阻塞其他合格字段发布。画像摘要和兼容文件不作为另一套维护来源。

公司静态字段保留 demo_unreviewed、api_supported、verified 的区别，旧标签不充当新核实证据。城市和方向证明继续来自岗位 API。未知字段保持未知；词表、枚举和身份规则的变化需要单独设计。

## 发布契约

两仓通过版本化文件包交接正式 API 配置、公司画像和产品需要的能力/可信状态；产品读取本地快照后调用招聘来源，不依赖在线 OPS 服务。公司/API 的评估过程留私有侧，用户岗位匹配评分与查询缓存仍属产品个人运行数据。

维护者生成完整版本包，包括 release_id、数据契约和核心版本、基准哈希、文件哈希及计数。私有发布器按白名单导出，隔离发布环境再次检查路径、字段、主体引用、兼容性和哈希；公开包不包含修复历史、私有原件、账户或本机路径。文件清单及只读验证见 scripts/lib/data-release-contract.mjs。

发布器只安装已批准快照，不在公有侧执行数据修复。多文件写入使用互斥锁、恢复日志与公开读取标记；中断时拒绝混读。data/public-release.json 记录公开版本及内容哈希。重复导入幂等，基准变化拒绝覆盖，回退以新的发布记录执行。只有目标公开分支实际包含版本才记为已发布。

新适配器先进入公开共享核心，经验证后私有侧才发布依赖它的配置。私有项目锁定并单向消费公开核心，不能复制维护第二套采集器；公开核心不导入私有代码。版本更新只安装正式数据，不开放用户修复口径。

## 目录与扩展

shared/job-search-core/assets 与 data 保存正式运行配置和数据；scripts/lib 提供共享采集、读取、归一化与契约验证。产品负责自己的编排和个人状态，产品之间不直接读取对方内部实现。多个产品确实需要且职责稳定的能力才提取到 shared；新增产品可增加同级 Skill。

私有仓库保存维护代码、已批准主数据、审核与发布元数据的 Git 历史；原件和 SQLite 账本独立备份，凭据另行管理。Git 不替代原件备份，也不能回退已发生的费用。当前公有 Git 的历史不在本次迁移中重写。

架构或公开使用方式变更时同步 README、Skill 与本契约。推送前分别检查 README 与 GitHub About 的描述和统计；无法核验 About 时明确记录。根目录 AGENTS.md 为本地协作说明，过程报告留在私有资料中。

## 验证

协作和维护顺序由 Agent 按各仓 AGENTS.md 与既有入口执行；不为流程约定再建设调度器、时效状态机或重复审核台账。按实际问题做局部修复和有针对性的测试，复用现有发布保护；无新变更或疑点时不重复全量验证。

在 shared/job-search-core 运行 npm test、npm run check:boundaries、npm run check:distribution；分发前还需在只有公开文件的干净副本中验证。故障测试须确认来源失败不会启动接口发现、写正式数据或阻塞其他可用来源。私有侧另测审核、发布、并发冲突、中断恢复、幂等与回退。
