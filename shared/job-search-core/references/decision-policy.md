# 求职任务的业务决策规则

新匹配使用[判断模型v5](assessment-v5.md)。缺证是不确定，可作为已审阅结果交付；无明确冲突但关键事实缺失使用“补资料后判断”。补问跨岗位聚合，每轮最多3组，优先改变判断的事实。工作年限仅经验参考，保留差距，结合职责、责任深度和成果判断放宽依据；不设统一宽限年数，不因年数不足自动否决，不保证雇主接受。

用户提出薪资需求时明确告知：“招聘信息中的薪资可能不准确，仅供参考，不代表实际录用待遇；不按薪资硬筛岗位。”不提供区间筛选或保证达标，只在最终主要判断相当时辅助排序，不改变主档位/投递动作。未给偏好不主动追问；未披露/口径不可比为未知，不推算薪数、奖金等。城市单独评估，不重复计入工作内容意愿。

这是 job-search、三个方向入口、岗位雷达和来源修复共用的产品政策。方向差异读 modes；雷达与修复的独立执行说明继续有效。用户本轮明确指令和已授权范围优先；不能把历史个案固化成所有用户的偏好。

## 识别当前任务，而非见到岗位就要求简历

| goal | 用户目标 | 先做什么 |
| --- | --- | --- |
| clarify | 多个可能任务，当前指代未明 | 先读可用历史，再问是哪项；不启动任一依赖分支 |
| consult | 咨询资格口径、材料要求或如何使用 | 先回答能确定的规则与限制；具体资格需准确本人条件和JD，不为解释问题启动全库搜索 |
| capabilities | 了解能查哪些行业/功能 | 运行 industries 或本地 catalog，直接答，不索要简历 |
| discover | 找机会、先看岗位 | 确定类型、公司或行业范围；不要求个人画像和评估批次 |
| match | 根据本人材料寻找适合岗位 | 整理材料和范围，采集后按已选范围全文匹配 |
| compare | 比较给定岗位/此前雷达候选 | 先定位完整 JD 和个人材料，不为有限目标强制问全市场行业 |
| explore | 不知道适合什么/转型探索 | 取得最小实际经历与意愿，解释可探索方向；不凭专业承诺适合 |
| radar | 持续关注、管理订阅、回看变化 | 读 job-radar/SKILL.md；无需简历；候选命中不是个人匹配 |
| repair | 查历史或修复招聘来源 | 读 recruitment-link-repair/SKILL.md；先定位主体/链接，遵守只读范围 |

模糊“找工作”先问求职阶段和目标/经历，不自动建订阅。用户已经说校招/社招/实习，或明确选择对应入口，不再问同一方向。实习经历不是本次实习意图；明确“社招、零正式年限”仍按社招。多个方向分开运行。PM 含义、活动/实习混合、多个未完成任务的“继续”有实质歧义才补问。

## 信息状态和约束

公司范围也可由明确业务细分限定：`conditions.businesses` 支持 any/all，和行业、公司条件取交集。用户已明确“只看游戏研发公司”时，无需再次选择宽行业；内部不额外加行业限制。业务偏好仅影响排序，不能变成硬筛选。雷达的岗位、行业、业务、公司中明确一项即可形成范围。

每个条件有 value、state、basis。state 为 explicit（本轮明确）、inherited（可读历史已明确）、unspecified（未指定）、conflict（冲突/待澄清）。explicit 且空列表表示明确不限；unspecified 值必须为空，不能补成用户已说不限。继承条件须有可定位历史，最新更正覆盖旧值并保留旧任务。相对日期依据本轮日期和用户时区解释；“应该/可能/最快”保留不确定性。

“只要稳定，其他没要求”等明确整体开放表述可在语境确实覆盖行业/城市时作为不限依据，并透明说明本轮解释，不要求用户逐字段重说不限；“做什么都行”可能只谈职能，不能自动扩展成全行业。文件名中的“资深运营”、过去的岗位头衔和工作行业只作为材料线索，不写成明确的目标职能/行业；是否继续该方向以本人表达为准。

条件维度：recruitment、industries、companies、cities、roles，以及可选 work_mode、ownership、size、availability。salary只记录用户已表达的参考偏好，不作搜索过滤条件。来源库 ID 必须由 industries/catalog 解析。职能不是行业，性质不是行业，使用 AI 不等于主营 AI，集团不等于子公司。

- 日常发现/匹配的行业未指定：若也未明确公司或业务范围，先列现有选项补问；不能根据履历代选。已明确公司或具体业务时，内部 industry_filters=['all'] 仅表示不额外加行业过滤，不能称用户选择全行业。给定岗位比较不要求行业选择。雷达的岗位、行业、业务、公司至少明确一项即可，不因只有岗位方向而强制补行业。
- 城市未指定：默认本轮不加城市过滤，告知并记录 unspecified，不强制追问。不把用户所在地、学校或工作经历当城市偏好。“不换城”需识别期望城市；“离家近/半小时通勤/同城远近”不支持，明确告知并忽略，不补问住址、交通方式、时段，也不作为后续验证目标。区域简称先解释为地区意图，需要明确城市集合时再澄清，不静默缩成几个大城市。远程是办公方式，不能当城市送入 normalizeCityFilters。
- 硬条件、偏好、探索、排除分别记录。语义不清才问“更看重/不能接受什么”；“最好外企”不排除所有私企。家人意愿与本人意愿分开。
- 明确公司与行业冲突：先核实分类和用户真正范围，不能绕过冲突或改查别家公司。细分行业映射显著扩大范围时说明并澄清。

## 按阶段问最少必要问题

每轮最多优先 3 组问题，围绕目前的决策，不把所有缺项塞成一个长问题。剩余缺口延后；已知不重问。用户说少问时仍不能编造画像、默认全量评估或接受虚假结论。

按需要用户作答的独立事实控制负担，不能把许多独立事实塞进“一组”冒充少问。先解决任务/来源范围等当前阻塞；同城距离和通勤不属于本包能力，不转成候选出现后的待办。实习是招聘身份，兼职是时间安排，不能问成“实习还是兼职”的互斥选择；先确认是否找实习，再独立核对可用时间。普通兼职若超出本包范围则说明。

1. 功能咨询/历史定位：先读本地信息，无需完整条件。
2. 岗位发现：需明确招聘类型和公司/行业范围，不需学历、简历、薪资或评估数量。可先列选项、定位已给公司。
3. 个人匹配：按方向读取已给事实，文字经历也有效。缺画像可以发现、拆解JD和判断有依据的维度，按[v5判断规则](assessment-v5.md)保留不确定，不编造事实，也不判定不会。用户目标仍为 match，不把降级步骤写成改了用户意图。
4. 评估：需完整JD、合法事实记录（可为空）和明确评估范围；范围已给直接保存，否则采集后展示数量再询问。
5. 交付：检查范围完成度和限制，不能把待核实、未评估与不匹配混成一类。

无附件/不可定位路径先核实材料所在；不可读文字只用可确认部分，缺截图不能假装已看。冲突简历核实时间线，不挑有利版本。接受脱敏职责、流程、成果区间；姓名电话、学校名、客户名称不是必填。团队成果须补本人行动，工具罗列/头衔/年限不是完整能力证据。

## 策略、范围和变化

按 [搜索策略](search-strategy.md) 分开检索、评估和批次。用户表达岗位倾向且未选择搜索方式时，必须先说明标题定向与全量 JD 综合判断各自的优劣并请用户选择；普通倾向不自动启用关键词预筛。已有明确选择直接沿用。确认定向后，已证实支持的 API 必须先搜索再返回，未明确证实支持的 API 全量获取列表后本地筛选；选择全量则结合标题和 JD 正文判断相关性。信息不足可继续读取材料、列行业/公司、定位旧任务，不能一律只给问卷。

续跑先读取真实任务/运行记录。增加城市/行业补查新增范围；“剩下全部”只扩大当前已采集范围内评估，不扩成全网。“再来20”从未评估项中取、不重复；剩余不足按实际数量。改变能力事实/意愿/到岗条件保留其他事实，建立新运行重评；仅改展示不改事实评级。明确最新则 refresh 本轮岗位，不能仅把缓存日期改成今天；不因此刷新公司基础标签或城市索引。

当前完整画像指纹包含 city_filters。把上海改成上海+杭州会使新运行画像变化：可以保留上海旧报告、复用合规上海JD，新增杭州补采；新报告若纳入上海旧岗位，也须按新画像重评，不能直接复制旧评级。明确“只评新增杭州”可将新运行评估范围限定在新增岗位，并链接旧报告，不能冒称上海旧评级已在新画像下有效。

跨方向新建隔离运行、补方向缺项，不复用岗位评级和城市证据。缺历史时说明缺失并索取报告或最小条件；两个可能的“继续”只问指代，不一并执行。

## 边界与异常

真实空、失败、部分覆盖、待核实分别处理。薪资仅参考、作息未知不承诺，同城距离/通勤不评估；厂级/所有制不保证稳定或轻松。不得夸大本人责任、篡改资格/建议、只看标题声称完成个人评估，或保证全市场无遗漏。可交付未评估候选/缩小明确数量，再进行正式判断。本包不包含自动投递、HR 联系；完成可支持的评估交付，不能声称外部操作成功。

雷达：只缺招聘类型就只补类型；已有时间/时区不重问。缺精确时间可先首轮检索，调度等待时刻确定；用户让你决定才用本地09:00并说明。多个类型分别订阅。放宽、暂停、静音先定位对象和具体变化，保存历史；有结果才称创建成功。只要求变化提醒时无变化保持安静。

修复：先用现有报告/历史定位主体，短名称不能猜分公司；缺本地历史如实披露。禁止盲改年份、跨主体替换、因无文件重抓全库。只分析时不执行会修改正式注册表的 repair-source。验证主体、方向和需要恢复的能力后才能应用授权内修改。
