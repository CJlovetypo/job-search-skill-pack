# 交付与完成标准

- capabilities/explore 的讨论：回答当前问题，明确需要什么才能进入具体岗位判断。
- discover：通过 render-discovery 生成候选 Markdown 和 JSON，保留官方链接、类型、地点、正文状态、覆盖和筛选限制；标题明确“尚未进行个人匹配”，不出现虚构能力/意愿/投递建议。可由 Agent 基于全文解释与目标职能的关系，不能冒充本人胜任结论。
- match/compare：新v5采用四页签Excel，岗位页十五列，保留原十二列并增加城市意愿匹配、薪资参考、证据充分性；旧v4运行仍十二列。缺证但已读完的岗位保留主表“信息待确认/补资料后判断”，不混入尚未读取/采集失败。JD/原始证据/日志留在运行目录，不塞隐藏页。任务快照一并留在运行目录，不向用户展示内部协议字段。
- radar：沿用独立 Markdown 日报与调度约定。首次发现不等于发布时间，本次未见不等于下架，调度未确认不称已启用。

已选范围 remaining=0 才称范围内审阅完成，同时报告已审阅数和仍不确定数；这不等于所有岗位已确定是否适合。待核实及范围外未评估仍披露。用户明确要求提前交付才允许 --allow-partial。空结果、获取失败、部分覆盖分别表达，不能把采集异常填成零招聘。文件实际生成并可读取后才给链接。

渲染只读取本轮保存的资料快照，不临时联网补公司信息、不改写模型判断。Excel 格式等具体约定继续由对应 workflow/excel-report 实现维护；改变展示不能改变事实。规模标签附统计主体与资料日期，不代表稳定性、薪酬或个人匹配。
